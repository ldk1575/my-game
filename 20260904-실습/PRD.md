# PRD — 내 Todo 앱 (AI에이전트 2기 · 2026-09-04 실습)

작성: AI에이전트 2기 · 노드「데이터베이스」실습 1부 산출물

## [무엇]

내 컴퓨터에서 도는 Todo(할 일) 앱. 데이터가 껐다 켜도 남는다.

## [기본 기능 — CRUD]

| 동작 | CRUD | SQL |
|---|---|---|
| 할 일 추가 | Create | `INSERT` |
| 목록 보기 | Read | `SELECT` |
| 완료 표시 | Update | `UPDATE` |
| 삭제 | Delete | `DELETE` |

## [저장]

로컬 무료 DB — **Node 24 내장 SQLite (`node:sqlite`)**, 파일 하나(`todo.db`)에 저장.

> 노드 문서는 `better-sqlite3`를 예로 들었지만 그건 네이티브 모듈이라 `node-gyp` 빌드 도구가 필요하다.
> Node 22부터 SQLite가 런타임에 내장되어 **설치와 빌드가 아예 없다.** 그래서 이 실습은 의존성 0개다.

## [내가 넣고 싶은 기능]

1. **마감일** — 할 일에 날짜를 붙인다. 지난 것은 눈에 띄게 표시한다.
2. **태그(카테고리)** — 할 일 하나에 태그 여럿, 태그 하나에 할 일 여럿 → **N:M, 연결 표 필요**
3. **오늘 할 일만 보기** — 마감일이 오늘인 것만 걸러 본다.

## [규칙]

- 무료 도구만. 비밀값은 `.env`로 (로컬 SQLite는 비밀값이 없어 이번엔 불필요).
- 로그인은 넣지 않는다. 넣게 되면 직접 만들지 말고 검증된 라이브러리로.
- **DB에 넣는 값은 문자열로 이어 붙이지 않고 파라미터화 쿼리로 처리한다.**
- `todo.db`와 `.env`는 `.gitignore`에 넣는다.

## 데이터 설계 — 표 세 개

오늘 배운 대로, 성격이 다른 것끼리 표를 나눈다.

| 표 | 담는 것 | 열 |
|---|---|---|
| `todos` | 할 일 한 건 | `id` · `title` · `is_done` · `due_date` · `created_at` |
| `tags` | 태그 종류 | `id` · `name`(유일) · `color` |
| `todo_tags` | **연결 표** | `todo_id` · `tag_id` |

### 왜 연결 표가 필요한가

> "A 하나가 B 여럿을, **동시에** B 하나도 A 여럿을 갖나?"

- 할 일 하나에 태그 여럿 (`업무`, `긴급`)
- 태그 하나에 할 일 여럿 (`업무` 태그가 붙은 할 일이 여러 개)

→ 양쪽 다 여럿이므로 **N:M**. 어느 표에도 상대를 다 적을 수 없어(한 칸에 여러 개를 욱여넣으면 검색이 깨진다)
`todo_tags` 연결 표를 하나 만들고, `N:M`을 **연결 표를 사이에 둔 두 개의 1:N**으로 푼다.

```
todos  1 ──< todo_tags >── 1  tags
        (todo_id)   (tag_id)
```

### 정규화 — 같은 걸 두 번 적지 않기

태그 이름(`업무`)을 할 일마다 적지 않고, `tags` 표에 **한 번만** 두고 `todo_tags`가 번호로 가리킨다.
태그 이름을 고치면 `tags` 한 곳만 고치면 끝이다.

### 색인 — 어디에 걸까

"색인 넣어줘"가 아니라 **실제 화면의 질문**으로 정한다.

| 화면의 질문 | 걸 색인 |
|---|---|
| "오늘 마감인 할 일만 보여줘" | `todos(due_date)` |
| "이 할 일에 붙은 태그 다 줘" | `todo_tags(todo_id)` |
| "이 태그가 붙은 할 일 다 줘" | `todo_tags(tag_id)` |

### 트랜잭션 — 어디에 걸까

할 일 하나를 추가하면 쓰기가 여러 번 일어난다 — `todos` 한 줄 + `tags` 신규분 + `todo_tags` 여러 줄.
중간에 실패하면 **태그 없는 할 일**이나 **주인 없는 연결 줄**이 남는다.
→ **전부 되거나, 전부 안 되거나**로 묶는다.
