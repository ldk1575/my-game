## 무엇을 만들었나

AI와 함께 일하는 방식을 **네 가지 축**으로 나눠 **16가지 유형** 중 하나를 알려주는 인터랙티브 테스트입니다. 질문은 **20문항**(축별 5문항).

수업에서 배운 **드라이버 / 네비게이터** 개념을 첫 번째 축으로 그대로 썼습니다.

| 축 | 한쪽 | 다른 쪽 |
| --- | --- | --- |
| 역할 | **D** 드라이버 — 직접 손댄다 | **N** 네비게이터 — 지시하고 판단한다 |
| 착수 방식 | **P** 명세형 — 정하고 시작한다 | **T** 반복형 — 만들며 정한다 |
| 통제 방식 | **V** 검증형 — 관문마다 확인한다 | **A** 위임형 — 맡기고 흐르게 둔다 |
| 목적 | **L** 학습형 — 이해가 남아야 한다 | **S** 산출형 — 결과가 나와야 한다 |

16유형 예시 — `DPVL` 설계도 든 장인 · `NPVL` 명세 쓰는 감독 · `DTAS` 일단 만드는 해결사 · `NTAS` 믿고 맡기는 의뢰인

### 질문을 만들 때 지킨 두 가지 원칙

성향 테스트가 실패하는 가장 흔한 이유는 **한쪽 보기가 명백히 "정답"으로 보이는 것**입니다. "확인하고 넘어간다 / 그냥 넘어간다" 같은 문항은 아무도 두 번째를 고르지 않아 진단이 되지 않습니다. 그래서 이렇게 만들었습니다.

1. **구체적인 상황으로 묻는다** — "나는 보통 어떤가" 대신 *"AI가 500줄짜리 변경을 한 번에 내놨다. 의도와 조금 다르다."* 처럼 실제로 부딪히는 장면을 제시합니다.
2. **양쪽 모두 정당한 선택으로 만든다** — 미덕 대결이 아니라 **트레이드오프**입니다. *"마감이 오늘인데 확인할 시간이 부족하다 → 핵심 흐름만이라도 직접 돌려 본다 / 내보내고 문제가 생기면 바로 대응한다"* — 둘 다 실무에서 쓰이는 판단입니다.

축 이름도 중립적으로 잡았습니다. `수용형`·`완성형`처럼 한쪽이 게을러 보이는 표현을 피하고 **`위임형`·`산출형`** 으로 썼습니다.

또한 `/clear`·`/compact`·`CLAUDE.md`·`/init`·`@파일`·`package.json`처럼 **실제로 만지는 명령어와 파일**을 보기에 그대로 넣었습니다. 추상적인 성향 질문보다 훨씬 정확하게 갈립니다.

## 설계 한 장

| 항목 | 내용 |
| --- | --- |
| **백엔드가 꼭 필요한 기능** | **결과 집계** — "지금까지 N명 중 나와 같은 유형 X%" |
| **화면만으로 되는 기능** | 질문 진행, 점수 계산, 유형 판정, 결과 표시 |
| **필요한 창구(엔드포인트)** | `POST /results` 결과 저장(Create) · `GET /stats?code=` 집계 조회(Read) |
| **다뤄야 할 비밀값** | Supabase 접속 키 → 코드에 적지 않고 환경변수로 |
| **호스팅** | 화면은 **GitHub Pages**, 데이터는 **Supabase**(무료) |

**왜 집계인가** — 여러 사람이 나눠 쓰고, 새로고침해도 남아야 하고, 조작을 막아야 하는 기능입니다. 화면만으로는 불가능해서 백엔드가 반드시 필요합니다.

## 교체가 쉬운 구조

지금은 집계가 목업입니다. 백엔드가 준비되면 **`fetchStats()` 안쪽만** 바꾸면 되고, 화면 코드는 손대지 않습니다.

**지금 (목업)**

```js
async function fetchStats(code) {
  const percent = MOCK_STATS.share[code] ?? 5.0;
  return { total: MOCK_STATS.total, count: ..., percent, mock: true };
}
```

**나중 (실제 호출)**

```js
async function fetchStats(code) {
  const res = await fetch(API + '/stats?code=' + code);
  if (!res.ok) throw new Error('집계를 불러오지 못했습니다');
  return await res.json();   // { total, count, percent }
}
```

응답의 **모양(이름표와 값)을 똑같이 맞춰 두었기 때문에** 교체가 한 곳에서 끝납니다. 이것이 수업에서 배운 **관심사의 분리**입니다.

로딩과 에러 화면도 미리 넣어 두었습니다 — 집계를 불러오는 중에는 "집계를 불러오는 중…", 실패하면 "집계를 불러오지 못했습니다"가 표시됩니다.

## 보안 점검 체크리스트

- [ ] 접속 키를 코드에 직접 적지 않고 **환경변수**로 빼기
- [ ] **서버에서 다시 검증** — 한 사람이 수천 번 결과를 넣어 통계를 망치지 못하게 막기
- [ ] Supabase **RLS를 켜고 정책 넣기** (안 켜면 누구나 데이터를 읽고 지울 수 있음)
- [ ] 집계 조회는 **읽기만** 허용, 남의 결과를 고치거나 지울 수 없게
- [ ] 무료 티어의 **한도와 일시정지 조건** 확인 (Supabase는 7일 미사용 시 일시정지)
